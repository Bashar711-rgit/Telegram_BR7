# unified_alerts — التنبيهات الموحدة (v12.0.0)

الحزمة المركزية لجودة التنبيهات: **لا مكرر، لا سبام، لا تنبيه غير مكتمل البناء**.

## لماذا وُجدت؟ (بلاغ الإنتاج الحقيقي — أكتوبر 2025)

بعد استعادة البوت على حساب Render جديد، ظهرت ثلاث شكاوى:

| الشكوى | السبب الجذري المُشخَّص | العلاج في هذه الحزمة |
|---|---|---|
| «سبام» — تنبيهات لرسائل قديمة جداً | `TELEGRAM_CATCH_UP=true` يجعل الحسابات السبعة تعيد تسليم تحديثات أيام الانقطاع؛ لا بوابة عمر في خط الأنابيب (`total_lag p50 ≈ 15.6 ساعة`) | **بوابة العمر** `gate.py` — إسقاط أي حدث أقدم من `MAX_EVENT_AGE_SECONDS` في أقرب نقطتين: بداية معالجة الحدث (قبل الإثراء وقبل أي كتابة DB) وبداية الإرسال |
| «مكرر» | الطبقات القائمة قوية (early-delivery + msg_hash + fingerprint + similarity) لكن الحدث يعتق في الطابور أثناء الازدحام ويعبر | فحص العمر الثاني عند `send` + عدادات موحدة تكشف أي تسريب |
| «تنبيه لم يُبنَ صحيحاً» | بطاقة HTML مقطوعة/وسوم غير متوازنة → Bot API يرفض (`can't parse entities`) أو يصل نص مبتور | **عقد البطاقة** `card.py` — فحص + إصلاح ذاتي (قص آمن، موازنة وسوم، تنظيف أزرار) أو إسقاط صادق مُحصى |
| طابور عالق 759 صف + evictions كل ثانية | backlog الـcatch-up يملأ `processing_queue` (سعة 500) | **الصيانة الذاتية** `maintenance.py` — حذف صفوف الطابور الأقدم من ساعتين عند الإقلاع ودورياً |

## البنية

```
unified_alerts/
├── __init__.py      الواجهة العامة + الإصدار
├── gate.py          UnifiedAlertGate — بوابة العمر (pipeline + send)
├── card.py          عقد سلامة البطاقة + الإصلاح الذاتي
├── stats.py         عدادات موحدة (singleton) → /health/full
├── maintenance.py   purge الطابور العالق (إقلاع + دوري)
└── README.md        هذا الملف
```

## نقاط الدمج (كلها فشل-آمنة — خلل الحزمة يفتح المسار ولا يُسقط تنبيهات صالحة)

| النقطة | الملف | الوظيفة |
|---|---|---|
| بداية `_process_event_pipeline` | `monitors.py` | بوابة العمر — إسقاط فوري للقديم قبل الإثراء/DB |
| بداية `_send_alert` | `monitors.py` | بوابة العمر — الاعتقاق أثناء الطابور |
| بعد `_build_alert` (مسار fallback) | `monitors.py` | عقد البطاقة — إصلاح/إسقاط صادق |
| بعد `build_alert_html` (مسار Bot API) | `alert_bot.py` | عقد البطاقة — نفس العقد للقالب الموحد |
| بعد `init_deduplicator` | `main.py` | صيانة الإقلاع (purge) |
| `_cleanup_loop` | `main.py` | purge دوري مع دورة التنظيف |
| `/health/full` → `unified_gate` | `monitors.py` | عدادات موحدة للرصد |

## الإعدادات (كلها حيّة — تُقرأ من CFG عند كل استدعاء، تعديل اللوحة يسري فوراً)

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `MAX_EVENT_AGE_SECONDS` | `1800` | أقصى عمر تنبيه (30 دقيقة). `0` = تعطيل البوابة كلياً |
| `ALERT_CARD_MAX_CHARS` | `4000` | حد نص البطاقة (وحدات UTF-16، أضيق من حد تيليجرام الصلب 4096) |
| `QUEUE_STALE_PURGE_SECONDS` | `7200` | حذف صفوف الطابور الأقدم من هذا العمر |

## الضمانات

1. **لا حذف بيانات مستخدم** — الـpurge يمس `processing_queue` حصراً (مخزن تشغيلي عابر)، بالعمر حصراً.
2. **بلا I/O في المسار الساخن** — البوابة والبطاقة عمليات متزامنة خالصة.
3. **أرقام صادقة** — كل إسقاط/إصلاح محصى ويظهر في `/health/full` تحت `unified_gate`.
4. **توافق كامل** مع طبقات dedup القائمة — لا تُستبدل ولا تُعطَّل؛ الحزمة تضيف طبقة العمر وسلامة البناء فقط.
